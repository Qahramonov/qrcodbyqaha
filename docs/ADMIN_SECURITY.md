# Администрирование и безопасность (v3)

## 1. Один администратор

* **Super Admin — только числовой Telegram ID из `SUPER_ADMIN_ID`** (`backend/.env`, у этого проекта — `8053614984`).
  Username (`@libPM`) — справочно и **никогда** не используется для проверки прав.
* Ролей `admin`/`moderator` в v3 нет: `users.role()` возвращает только `super_admin` или `user`; старые строки `admin_roles`
  (moderator из v1) игнорируются; API смены роли принимает только понижение до `user`.
* Роль вычисляется **на сервере при каждом запросе** по ID из Telegram-апдейта или из сессии приложения. Подставить чужой ID в
  параметр (`user_id=8053614984`, заголовок `X-User-Id`, поле JSON) — ничего не даёт; это покрыто тестами.

## 2. Админ-раздел невидим для всех остальных

| Точка входа | Что видит не-админ |
|---|---|
| Меню бота (`/start`, `/menu`, онбординг) | кнопки «👑 Super Admin» нет |
| `m:admin` (подделанный callback) | обычное главное меню, без сообщения об ошибке |
| Админ-callback'и `ax:` `adm:` `bc:` | «мёртвая кнопка»: пустой ответ, без текста и alert'а |
| Админ-шаги FSM (`AX:*`, рассылка) | состояние сбрасывается молча, сообщение ничего не делает |
| Админ-команды (`.logs`) | ответ «Неизвестная команда» (в личке) или тишина (в бизнес-чате) — как у несуществующей команды; нет в `.help`, `.commands`, подсказках «Возможно:», каталоге команд панели и API `/commands` |
| REST API (43 админ-маршрута) | `404 not_found` — **тот же ответ, что у несуществующего адреса**; без токена и админ-, и несуществующие адреса отвечают одинаковым `401` |
| Swagger / OpenAPI | выключены по умолчанию (`API_DOCS_ENABLED=false`), т.к. показывают список маршрутов |
| Приложение | плитки Super Admin нет; маршруты `/admin/*` роутер не открывает (возврат на главную), запросы к админ-API не отправляются |

Каждая такая попытка записывается в аудит: `security.admin_callback_denied`, `security.admin_state_denied`,
`security.admin_command_denied`, `security.admin_api_denied` (Super Admin видит их в «Безопасность → Журнал аудита»).

Тесты: `tests/backend/test_v3_admin_hidden.py` (перебирает **все** админ-маршруты API и все входы бота), `test_v3_access.py`,
`flutter_app/test/router_test.dart` и `screens_test.dart` (подделанные поля роли, `/admin/*` для обычного пользователя).

## 3. Что может Super Admin

Панель в боте (23 раздела: Dashboard с фильтрами Сегодня/7/30 дней, пользователи, подключения, права, карточки управления, AI,
AI-двойник, AFK, Mute, медиа, игры, менеджер команд, планировщик, модули, подписки, рассылка, аналитика, безопасность, логи, БД,
система, диагностика, оформление) и 16 экранов в приложении. Опасные действия — только с подтверждением:

* **Аварийная остановка** — ввод слова `STOP` (снятие — `RESUME`); мгновенно останавливает действия бота в бизнес-чатах.
* **Рассылка** — черновик → предпросмотр себе → оценка числа получателей → запуск с `confirm`.
* **Возврат Stars** — только явным подтверждением конкретного платежа.
* **Ограничение пользователя** — с причиной; бот и приложение перестают его обслуживать сразу (каждый API-запрос проверяет статус).
* **Передачи Stars/подарков нет в коде вообще.**

Чужую переписку администратор не видит: карточка пользователя показывает только счётчики и статусы
(«Private chat contents are never exposed to administrators»). Изменение чужих настроек — только через добровольное
**делегирование** пользователя ([PERMISSIONS.md](PERMISSIONS.md#3-делегирование-помощь-администратора--отдельно-от-прав-telegram)).

## 4. Секреты

* `BOT_TOKEN` — только в `backend/.env` (права 600, в `.gitignore`). Не попадает в код, APK, тесты, документацию, логи
  (редактор логов маскирует токены, в том числе внутри URL), ZIP-архив проекта (`git archive` без `.env`).
* Ключи AI — там же, опционально.
* Приложение хранит только свои токены сессии (Android Keystore через `flutter_secure_storage`, `allowBackup=false`).

## 5. Приложение ↔ API

* Сопряжение: одноразовый код `/app` (8 символов, 5 минут, хранится только хеш), привязка к устройству.
* Access-токен 1 час, refresh 30 дней с ротацией; сессии видны и отзываются (в приложении и боте).
* Перебор кодов: окна по IP + глобальная блокировка сопряжения на 15 минут после 50 неудач за 10 минут (уведомление Super Admin).
* Лимиты: 600 запросов/мин на IP, 240/мин на сессию; тело запроса ≤ 2 МБ; заголовки `nosniff`, `DENY`, `no-store`.
* API слушает **127.0.0.1** по умолчанию. Удалённо — только `API_REMOTE_ENABLED=true` **и** TLS-сертификат (`API_SSL_CERTFILE`,
  `API_SSL_KEYFILE`); без сертификата сервер принудительно остаётся на localhost. Приложение пускает `http://` только на
  `127.0.0.1/localhost/10.0.2.2`, остальное — `https://`.

## 6. Приватность и AI

* AI видит историю чата только если включено «Хранить контекст чатов» (`ai_store_history`); историю можно очистить по чату.
* AI-двойник учится **только на примерах, которые владелец добавил сам** (`.twin learn`, приложение); чужие сообщения в обучение
  не идут. Ответы AI подписываются (`ai_disclosure`, по умолчанию «🤖 AI» на языке владельца).
* Экспорт и удаление своих данных: `GET /api/v1/export`, кнопка в приложении, `/privacy` в боте.

## 7. Чек-лист после установки

1. `SUPER_ADMIN_ID` = ваш числовой ID (узнать: @userinfobot или `/start` → «Мой аккаунт»).
2. `API_HOST=127.0.0.1`, `API_DOCS_ENABLED=false`.
3. В Telegram выключены права на Stars/подарки/username.
4. `./scripts/status.sh` → `bot_polling: true`.
5. После смены токена у @BotFather (`/revoke`) — обновите `BOT_TOKEN` в `.env` и `./scripts/restart.sh`.
